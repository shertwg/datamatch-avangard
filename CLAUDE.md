# CLAUDE.md — DataMatch: прогноз продаж билетов ХК «Авангард»

## Цель
- Предсказываем `tickets_total`: сколько билетов продастся **за всё время продаж** на каждый из 17 test-матчей (M086–M102, сезон 2025/26) в каждой из 8 ценовых зон, всего 136 строк.
- Формат: заполнить `tickets_total` в копии `data/submission_template.csv` (`match_id,zone,tickets_total`), сохранить как `predictions.csv`. Значения целые, ≥ 0.
- Метрика: RMSE по всем 136 строкам на скрытых фактических продажах.
- Baseline: среднее `tickets_total` по зоне за прошлые матчи. Модель должна быть лучше него.
- Что сдаём: `predictions.csv`; Jupyter-ноутбук, который с нуля воспроизводит прогноз; README (как запустить и какие допущения приняты); презентацию в PDF (до 10 слайдов: подход и признаки, RMSE против baseline в целом и по зонам, разбор ошибок, выводы для клуба).
- Таргет для train: сумма `tickets` из `sales_daily.csv` по (match_id, zone).

## Данные (`data/`, UTF-8)
- `matches.csv` (102): матч. `match_id`, `season`, `date`, `time`, `weekday` (1=пн), `opponent`, `opponent_khl` (ключ к khl_games), `sales_open`, `part` (train 85 / test 17).
- `sales_daily.csv` (23 039): продажи в зоне за день. `match_id`, `zone`, `date`, `days_before` (0 = день матча), `tickets`. Нет строки → в этот день 0 продаж.
- `season_tickets_daily.csv` (1 586): продажи абонементов. `season`, `date`, `zone`, `package_matches`, `abonements`.
- `zones.csv` (816): зона на матче. `match_id`, `zone`, `seats`, `season_tickets` (места, занятые абонементами). Есть и для test.
- `khl_games.csv` (2 033): матчи КХЛ. `season`, `date`, `stage`, `home`, `away`, `home_goals`, `away_goals`. Фактически данные идут до 2025-11-19.
- `submission_template.csv` (136): `match_id`, `zone`, пустой `tickets_total`.
- Зона 1 самая дорогая, зона 8 самая дешёвая. Цен в данных нет.

## Жёсткие правила
- **Дата отсечки 15.12.2025.** Никаких данных после неё, это утечка. Продажи в файлах есть до 14.12.2025 включительно.
- `tickets_total` — целое, `0 ≤ tickets_total ≤ seats − season_tickets` (клиппинг по `zones.csv`).
- Абонементы и бесплатные билеты в `tickets` не входят. Таргет — только разовые билеты.
- Продажи уже начались на 6 test-матчей (M086–M091). Прогноз = итог за всё время, включая уже проданное, поэтому `tickets_total` не меньше уже проданного.
- Валидация: только `GroupKFold` по `match_id` или разбиение по времени (обучаемся на ранних матчах, проверяем на поздних). Никакого случайного split по строкам.
- Исторические средние (по зоне, сопернику и т. п.) считаем только по матчам, которые были **раньше** текущего (expanding/shift). Внутри CV считаем их только на train-фолде.
- Для train-матчей не используем в признаках продажи, которых не было бы на момент прогноза (полный итог = таргет).
- Внешние данные — только общедоступные. Данные хакатона не публикуем.

## Структура репо и соглашения
```
data/        исходные данные (только чтение)
docs/        задание: task.pdf, task_readme.md, LICENSE.md (только чтение)
src/data.py        load_raw(), build_table(as_of) — единая сборка таблицы match_id × zone
src/validation.py  схема валидации
notebooks/   01_eda.ipynb (ArinaPig), 02_baseline.ipynb (augustteske), 03_model.ipynb (sharbl4),
             solution.ipynb — финальный, с нуля выдаёт predictions.csv
```
- Ноутбуки нумеруются `NN_name.ipynb` в порядке запуска. Чужие ноутбуки без договорённости не правим.
- Данные во всех ноутбуках берём только через `src.data.build_table(as_of=...)`: обрезка по as_of в одном месте.
- Допущение: `seats` и `season_tickets` из zones.csv считаются известными заранее (не обрезаются по as_of).
- Признаки из `khl_games` и `season_tickets_daily` делает sharbl4 отдельно, в build_table их нет.
- Пути только относительные (`../data/matches.csv` из notebooks/), без абсолютных `C:\...`.
- `random_state=42` везде (модели, KFold, сэмплирование).
- Python 3.12, библиотеки только из `requirements.txt` (pandas, numpy, matplotlib, seaborn, scikit-learn, catboost, jupyter). Новую библиотеку добавляем в requirements.txt.
- CSV читаем с `encoding="utf-8"`. Даты парсим через `pd.to_datetime`.
